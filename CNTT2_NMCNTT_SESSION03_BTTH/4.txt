PHẦN 1: PHÂN TÍCH CHẨN ĐOÁN VÀ VAI TRÒ TÀI NGUYÊN HỆ THỐNG
1. Chẩn đoán nguyên nhân máy bị lag qua Task Manager (%CPU và %RAM)
• Chẩn đoán chỉ số %RAM (Gần ngưỡng 100%):
- Mỗi tab Chrome ngốn trung bình 150 MB - 300 MB RAM. Với 20 tab Chrome mở đồng thời, lượng RAM tiêu tốn đã lên tới khoảng 3 GB - 5 GB.
- Trình soạn thảo VS Code cùng các tiện ích mở rộng (extensions) và trình thông dịch Python chiếm khoảng 1 GB - 2 GB RAM.
- Hệ điều hành Windows 11/10 duy trì hoạt động ngầm tiêu tốn khoảng 2.5 GB - 3 GB RAM.
- → Tổng dung lượng RAM yêu cầu vượt quá dung lượng RAM vật lý (8 GB), dẫn đến hiện tượng tràn bộ nhớ (RAM Bottleneck).
• Cơ chế Swap File (Pagefile) và hiện tượng đứng máy:
- Khi RAM bị đầy (100%), Hệ điều hành buộc phải dùng cơ chế Bộ nhớ ảo (Virtual Memory): chuyển bớt dữ liệu tạm thời từ RAM ghi tạm vào một file ẩn trên SSD gọi là Swap File / Pagefile.
- Dù SSD có tốc độ nhanh, tốc độ truy xuất của SSD (khoảng 500 MB/s - 3500 MB/s) vẫn chậm hơn hàng chục lần so với RAM (tốc độ RAM DDR4/DDR5 đạt từ 20,000 MB/s - 50,000 MB/s).
- CPU phải tốn liên tục các chu kỳ xử lý (%CPU tăng cao do I/O Wait) để chờ SSD đọc/ghi chuyển đổi dữ liệu qua lại giữa RAM và Swap File, làm cho toàn bộ hệ thống bị đứng cứng (Freezing/Lag).
2. Phân biệt vai trò giữa RAM (Bàn làm việc) và Storage (Ngăn tủ)
Sự phối hợp trong mô hình IPO (Input - Process - Output) được ví như công việc tại văn phòng:
• RAM — Bàn làm việc (Bộ nhớ tạm thời / Volatile Memory):
- Vai trò: Là không gian chứa các tài liệu, công cụ mà CPU đang trực tiếp xử lý ở thời điểm hiện tại (20 tab Chrome, VS Code, ứng dụng Python đang chạy).
- Đặc tính: Tốc độ truy xuất cực kỳ nhanh nhưng dữ liệu sẽ biến mất hoàn toàn khi tắt máy hoặc mất điện. Mặt bàn (8 GB) bị quá tải khi bày quá nhiều tài liệu cùng lúc.
• Storage (SSD) — Ngăn tủ tài liệu (Bộ nhớ lưu trữ lâu dài / Non-volatile Memory):
- Vai trò: Là nơi cất giữ, bảo quản toàn bộ dữ liệu hệ thống, file mã nguồn Python, phần mềm cài đặt kể cả khi máy đã tắt hoàn toàn.
- Đặc tính: Dung lượng lớn (256 GB), lưu giữ dữ liệu an toàn lâu dài nhưng tốc độ truy xuất chậm hơn nhiều so với RAM. Khi mặt bàn (RAM) quá tải, người dùng phải liên tục chạy ra mở ngăn tủ (SSD) để đổi tài liệu, gây ra hiện tượng chậm trễ.
3. Phân tích bẫy dữ liệu: Lưu code tại C:\Windows\System32\Code của tôi
• Nguy cơ bảo mật và phân quyền: System32 là thư mục chứa các tệp tin hệ thống cốt lõi của Windows. Thao tác tại đây đòi hỏi quyền Quản trị viên (Administrator), dễ gây ra lỗi không cấp đủ quyền cho Python khi tạo/ghi file.
• Nguy cơ mất trắng dữ liệu: Ổ C: là phân vùng cài đặt Hệ điều hành. Khi máy bị lỗi Win, dính virus hoặc cần Format để cài lại hệ điều hành, toàn bộ dữ liệu tại ổ C: (bao gồm cả thư mục System32) sẽ bị xóa sạch hoàn toàn.
• Quy chuẩn đặt tên: Tên thư mục Code của tôi chứa tiếng Việt có dấu và khoảng trắng, gây lỗi phân tách tham số khi thực thi lệnh trên Terminal/CLI hoặc khi chuyển đổi môi trường mã nguồn.
